## GitHub Actions baseline

1. Every workflow declares `permissions:` — either a top-level default or per-job — narrowed to exactly what each job needs (`contents: read` unless a job genuinely writes). GitHub's own default token, when neither is set, is read-write on every scope the workflow can reach — `infra.github-actions.policy`'s own rego enforces this structurally; `infra.github-actions.scan`'s own `zizmor` (`excessive-permissions`) independently flags the same risk.
2. Every third-party action is pinned to a commit SHA, never a floating tag (`uses: actions/checkout@v4` is a floating tag; `uses: actions/checkout@<40-char sha>` is pinned) — a tag can be moved by its own publisher, silently changing what a workflow runs. `zizmor`'s own `unpinned-uses` finding catches this for real (confirmed against a real binary).
3. `pull_request_target` is used only when the workflow genuinely needs write access or secrets against a fork's own PR — never combined with checking out and running the fork's own untrusted code, the single most common GitHub Actions supply-chain mistake.
4. A secret is referenced only through `${{ secrets.X }}`, never echoed, logged, or interpolated into a shell command directly (`run: echo ${{ secrets.X }}` leaks it into the job log) — pass it through an environment variable (`env: TOKEN: ${{ secrets.X }}`, then `run: use "$TOKEN"`) so the runner's own log-masking applies.
5. `${{ github.event.* }}` values from an untrusted trigger (an issue title, a PR body) are never interpolated directly into a `run:` shell command — a value an external contributor controls becomes shell injection the moment it is; pass it through `env:` and reference the environment variable instead, the identical reasoning rule 4 already states for secrets.
6. `infra.github-actions.policy` (conftest) runs with `input: "render"` — for this addon, Render is a byte-identical copy of the workflow's own source (no templating step exists to make source and rendering differ, unlike Helm), so this is a consistency choice with the other OPS-target-scoped checks, not a hazard-avoidance one.
