## 21. Config loading (`internal/config`)

Built in phase 2 (see `ai-flow-cli/AGENTS.md` repository status). Its own code and tests are authoritative over this section, per the precedent `AGENTS.md` already sets for `internal/envelope`, `internal/cli` and `internal/ops/exec` — this is a description of what landed, not a spec to re-derive.

- **Path resolution is the only "precedence" that exists**: `--config` overrides `<home>/config.json`, full stop (`config.ResolvePath`). No `config.json` field has an environment-variable or flag override — the command catalog never gives one a flag equivalent, and the spec's own Secrets table is explicit that tokens come from the environment only and never touch the config file. `config.Load` backfills exactly one field-level default when absent (`defaults.guard_idle_hours` → 8); nothing else is layered.
- **Loading and validating are two separate steps, on purpose.** `config.Load` only checks that the file exists, decodes with `DisallowUnknownFields`, and carries a supported `schema_version` — the minimum a caller like a future `stage start` needs to get a usable `*Config` without re-running every documented rule on every invocation. `config.Validate(cfg, kubeconfigPath)` runs the full rule set (team/environment/target-map/risk-gate/standards-source rules, the kubeconfig-context warning) and is what `ai-flow config validate` calls; a `Load` failure and a `Validate` failure are both possible independently.
- **Aggregate, don't stop at the first hit**: `Validate` joins every rule violation with `errors.Join` (`04-errors.md` §8), and the CLI layer flattens that into one `error.details[]` entry per violation — a developer running `config validate` sees every problem in one response, not one round trip per field.
- **No interactive prompts, ever** — consistent with the top-level `ai-flow-cli/AGENTS.md` invariant that the CLI never asks a question. Unlike most exit-4 `needs_input` cases, an invalid config has no `resume_with` a caller could resupply — it is exit 6 `config_invalid` (a document that does not have its documented shape, the same class as `pack_invalid`); a missing `config.json` is exit 3 `missing_artifact`, the same precondition class a missing handoff artifact uses.
- Secrets (tracker tokens, host tokens) are read from the environment directly by the packages that need them (phases 4-5 onward) and are never merged into `Config` at all — there is no secret-shaped field to redact, so there is nothing for a future `--print-config` (not a command the catalog names; none exists) to guard.
- Config values that are durations are exposed as `time.Duration` through accessor methods on the struct that stores the raw integer (`Defaults.MutationTimeout()`, `Defaults.TestTimeout()`, `Defaults.GuardIdleDuration()`, `Ops.ToolTimeout()`) — the JSON field itself stays a plain integer of minutes or hours, matching the spec's own `config.json` example byte for byte; call sites use the accessor and never re-parse the integer themselves.
